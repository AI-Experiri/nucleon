# 0008 — 2026-08-15 — the loader lands

## Built

- nucleon/src/loader/: error.rs (refusals with found-vs-supported),
  container.rs (GGUF v3 byte parser, sanity caps, alignment),
  config.rs (metadata keys to Qwen3Config in FamilyConfig),
  dequant.rs (F32 passthrough + Q8_0 blocks), yamf.rs (the gate:
  expected-tensor contract, dims reversal, tied lm head by absence,
  stop-set assembly, minijinja-validated ChatTemplate),
  gguf_builder.rs (test-only synthetic GGUF writer + reference Q8_0
  quantizer). 33 loader tests; 111 workspace tests green; fmt and
  clippy -D warnings clean.
- Dependencies: nucleon now depends on half, memmap2, minijinja
  only; safetensors/serde/serde_json/anyhow/thiserror/tokenizers
  removed from the crate (tokenizers returns with its block).
  candle-core 0.11 stays dev-only as the oracle.

## What broke, honestly

- lib.rs got the doc-comment mention of the loader but not the
  `pub mod loader;` line: 45 old tests passed and none of the new
  ones existed. Caught by counting tests, not by the compiler.
- ChatTemplate::source() tried to return a borrow of a temporary
  (minijinja's get_template returns a value); fixed by storing the
  source string alongside the environment.
- THE ORACLE EARNED ITS KEEP ON ROUND ONE: our Q8_0 rule checked
  total element count % 32; candle refused the fixture because the
  real ggml constraint is per ROW (dims[0] % 32; blocks never span
  rows). The mini fixture itself was an illegal Q8_0 tensor. Rule
  fixed to row_len, fixture regeometried (hidden 32), and the
  roundtrip fixture rewritten so every block contains -127 (d = 1.0
  exactly, integer-exact roundtrip) — the first version only had
  amax = 127 in its first block.
- Four clippy lints (dead env field until the chat chapter, two
  manual is_multiple_of, one let-and-return).
